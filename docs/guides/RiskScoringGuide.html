Risk Scoring Guide

Create weighted rules, test JavaScript predicates, and rank DLP alerts by combined risk.

Features

  • Evaluates weighted Boolean rules against normalized DLP alerts and ranks each alert by the total weight of all matches.
  • Includes a collapsible Built-in detectors group with editable weights and parameters, plus reusable custom rule collections that can be imported or exported.
  • Provides isolated JavaScript rule testing and optional OpenAI-assisted rule generation without sending uploaded alert rows to OpenAI.

How risk scoring works

  1. Upload one or more Forcepoint DLP alert CSV or XLSX files.
  2. Select rules in the rule list and assign each one a non-negative risk weight.
  3. Select RUN ALL. Every enabled rule is evaluated for every alert.
  4. The tool adds the weights of all matching rules and ranks alerts from highest to lowest score.

The ranked result table is the review workspace. Use the funnel beside any result column to filter by text or sort in either direction. Filters can be combined across columns; the alert count, pagination, and CSV export all follow the filtered result set. Select Clear filters to return to the complete ranking. The detector list remains in its intentional built-in/custom order so it is easy to manage rules.

The Built-in detectors group can be collapsed to make more room for custom rules. Predefined rules are maintained by the application. You can enable or disable them and change their weight. Rules with parameters also expose those parameters in the editor, and Default restores their original weight and settings before you save. Their names, descriptions, and matching logic cannot be changed or deleted.

Email Broadcast Multiple Destination Domain counts unique destination domains on each alert. For Gmail, Google, Yahoo, Microsoft, and Outlook destinations, it counts unique local parts instead so multiple consumer-mail recipients are retained. Set Minimum destination domains to choose the match threshold. Email Sent to Self (by character) compares normalized sender and destination text and matches when they share a sequence at least as long as Minimum matching characters, which defaults to five.

Using the AI Rule Generator

  1. Select the settings button beside Guide to open the settings box. Enable Ignored values to exclude alerts using the source and destination patterns saved in Alert Analyzer.
  2. In AI Rule Generator, enter your OpenAI API key, choose how many days it may be kept in this browser, and select Save API key.
  3. Select New Rule, then use the larger prompt box to describe the condition, fields, thresholds, separators, and exceptions in plain English. Select Generate rule.
  4. Review the generated rule name, description, recommended weight, and JavaScript carefully, then select Save.
  5. Use RUN to validate the rule against uploaded alerts before enabling it for RUN ALL.

The API key is stored only in the current browser for the selected retention period. Generating a rule sends your written instruction to OpenAI, but it does not send the uploaded CSV rows. Generated code should always be reviewed before it is run.

The generator combines your prompt with the documented execution environment and asks for a name, description, recommended weight, and JavaScript statement block. It places those values into a new custom rule without saving or enabling it. This review step is deliberate: confirm the field names, parsing assumptions, and return value before selecting Save.

The ranked table displays a compact alert summary plus Score and Triggered rules. Row copy and CSV export retain every original uploaded column.

Example request

Match Network email alerts when the attachment is larger than 10 MB and the destination is outside example.com.

A useful generated rule should verify that row.Channel is email, parse row.Size as kilobytes, split multiple values in row.Destination on semicolons, and return true only when both conditions match.

Creating a JavaScript snippet

Select New Rule, enter a unique name and risk weight, then write a statement block that returns true for a match and false otherwise. The current normalized alert is available as row; all normalized alerts are available as rows; and i is the current zero-based row index.

Available row properties are ID, IncidentTime, EventTime, Source, Policies, Channel, Destination, FileName, Details, Size, and Status. Values are strings. Multiple filenames and destinations are normalized to semicolon-separated text.

  • Use pure, synchronous JavaScript. Network, browser storage, DOM, and dynamic-code APIs are unavailable.
  • Handle blank values and return a Boolean on every path.
  • Use RUN to inspect one rule before enabling it for combined scoring.
  • Only import snippets from sources you trust, and review generated code before running it.

Variables and data model

row
The normalized alert currently being evaluated. Read fields with exact, case-sensitive names such as row.Source or row.FileName.
rows
The complete normalized dataset. Use it for comparisons such as finding destinations that occur only once. Do not modify this array.
i
The zero-based position of row inside rows. It is useful when comparing the current alert with neighboring or earlier alerts.

All row fields are strings, including Size. Blank or unavailable values are empty strings. Size represents kilobytes and may use uppercase scientific notation, such as 3.12E+4. Validate it before converting. FileName, Policies, and Destination can contain multiple values separated by semicolons.

How to structure a reliable snippet

  1. Convert the field to a string and handle a blank value first.
  2. Normalize case and whitespace when the comparison should be case-insensitive.
  3. Split multi-value fields, trim each item, and remove empty items.
  4. Validate numbers or dates before comparing them.
  5. Apply explicit exceptions before the match condition.
  6. End with return true; or return false;; every execution path should produce a Boolean.
const destinations = String(row.Destination || "")
  .split(";")
  .map(value => value.trim().toLowerCase())
  .filter(Boolean);
if (!destinations.length) return false;

const sizeText = String(row.Size || "").trim();
if (!/^\d+(?:\.\d+)?(?:E\+?\d+)?$/.test(sizeText)) return false;
const sizeKb = Number(sizeText);

const trustedDomain = "example.com";
const hasExternalDestination = destinations.some(value =>
  !value.endsWith(`@${trustedDomain}`) && value !== trustedDomain
);
return sizeKb > 1024 && hasExternalDestination;

Cross-row rules

Use rows only when the condition depends on the dataset, because scanning the full array for every alert is more expensive than a row-only test. This example identifies a destination text that appears only on the current row:

const destination = String(row.Destination || "").trim().toLowerCase();
if (!destination) return false;
let occurrences = 0;
for (const candidate of rows) {
  if (String(candidate.Destination || "").trim().toLowerCase() === destination) occurrences++;
  if (occurrences > 1) return false;
}
return occurrences === 1;

Prompt-writing checklist

A precise AI prompt states the channel or scope, exact field names, units, how multiple values should be treated, exceptions, and boundary behavior. For example:

Match only Network email alerts. Parse row.Size as KB and require it to be
strictly greater than 10 MB. Split row.Destination on semicolons. Match when
at least one destination is outside example.com, but ignore blank destinations
and the trusted partner.org domain. Return false when Size is invalid.

Avoid vague requests such as “find risky emails.” State what constitutes risk and provide one matching and one non-matching example when the logic is nuanced.

Built-in detector: attachment resembles a ransomware note or encrypted file

This predefined detector recognizes common ransom-note names, encryption wording, suspicious appended identifiers, and encrypted-file extensions. Open it in the rule editor to customize its encExtRegex setting.

"use strict";
const fn = String(row.FileName || "");
if (!fn) return false;
const names = fn.split(/[\n\r;,|]+/).map(s => s.trim()).filter(Boolean);
const noteRegex = /\b(read[_\- ]?me|how[_\-\s]?to(?:[_\-\s]?(decrypt|restore|recover|recover_files|restore_files))|howto[_\-\s]?(decrypt|restore|recover)|decrypt(?:ion)?|decryption|restore(?:_files)?|recover(?:_files)?|ransom|ransomware|!!!|_readme)\b/i;
const otherSuspicious = /\b(files[_\-\s]?(are[_\-\s])?encrypted|your[_\-\s]?files|restore[_\-\s]?your[_\-\s]?files|recover[_\-\s]?your[_\-\s]?files|decrypt_your_files)\b/i;
const encExtRegex = /\.(locked|encrypted|enc|crypt|crypted|crypt0|crypt1|cryp|crpt|lock|crypto|cipher|crypted-files|encrypted-files|vault|enc[0-9a-z]{2,8})$/i;
for (const name of names) {
  if (noteRegex.test(name) || otherSuspicious.test(name) || encExtRegex.test(name)) return true;
  if (/\.(txt|htm|html|hta|url)$/i.test(name) && /(read[_\-\s]?me|how[_\-\s]?to|decrypt|restore|recover|ransom)/i.test(name)) return true;
  if (/[!]{2,}/.test(name) || /_+readme/i.test(name) || /\b(encrypted|locked|lockedfiles|locked_files)\b/i.test(name)) return true;
  const idExtension = name.match(/\.([0-9a-fA-F]{6,12}|[0-9a-zA-Z]{6,12})$/);
  if (idExtension && (name.match(/\./g) || []).length >= 2) return true;
}
return false;

Sample: destination email uses a subdomain

const dest = String(row.Destination || "");
const emailRe = /^[^@\s]+@([A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)+)$/;
for (const part of dest.split(/;/)) {
  const match = emailRe.exec(part.trim());
  if (!match) continue;
  const domain = match[1].toLowerCase();
  if (["onmicrosoft", "salesforce", "imcap", "landbank.com"].some(value => domain.includes(value))) continue;
  const labels = domain.split(".").filter(Boolean).slice(0, -1);
  if (labels.filter(label => label.length >= 4).length >= 2) return true;
}
return false;
